WHAT'S NEW IN THIS VERSION
───────────────────────────────────────────────────────────
1. All 6 service forms were redesigned to match the official
   printed application forms you uploaded (Limited Company,
   Sole Proprietorship, Birth Certificate, Passport):
     • passport-form.html            (New Passport Application)
     • passport-renewal-form.html    (Passport Renewal — NEW)
     • passport-missing-form.html    (Missing Passport — collects
       the SAME information as a New Passport Application, plus
       an old/missing passport number field, with the SAME
       5-package processing/pricing picker)
     • birth-certificate-form.html
     • sole-proprietorship-form.html
     • limited-company-form.html     (maroon theme, two owners,
       matches the printed Limited Company form)

   Every Google Form link on the site (index.html and
   business-registration.html) was replaced with these real,
   built-in forms so payment + email + admin tracking all work
   the same way for every service.

2. The Admin Dashboard (admin.html) was rebuilt with a nicer
   look — sync-status badge, six stat cards, a searchable /
   sortable / filterable table, CSV export, and a details modal.

2c. All three passport forms now show upload widgets for the
   Client Passport Photo, Ghana Card, and Birth Certificate,
   matching the printed form. Chosen files are shown as a
   preview only — they are NOT uploaded or stored on the
   server (to keep things simple and avoid extra storage
   costs). Applicants are still asked to send the real files
   via WhatsApp/email, same as before.

2d. New Passport Application and Missing Passport now collect a
   much fuller set of information — Residential Address,
   Education, Parent / Guardian details (father + mother), one
   Grandparent, two Guarantors, and a Witness — in addition to
   Personal Information and Service/Payment. They collect
   exactly the same fields as each other (Missing Passport just
   adds one extra field: the old/missing passport number).

   Passport Renewal deliberately stays simple — just the photo/
   document uploads, Personal Information (with a Previous /
   Current Passport Number field added), and Service/Payment.
   No residential, education, guarantor, or witness sections —
   a renewal doesn't need re-vetting the same way a brand-new
   application does.

2e. The admin password is no longer hardcoded inside admin.html
   (previously anyone could view the page source and read it —
   that's fixed now). It's verified server-side via /api/login,
   and the admin can change it any time from inside the
   dashboard with the "Change Password" button in the header.
   See "CHANGING THE ADMIN PASSWORD" below.

2f. The admin dashboard's detail view now has a "Print / Save
   PDF" button. It opens a formatted, letterheaded version of
   the application in a new tab and triggers the browser's
   print dialog — choosing "Save as PDF" there produces a PDF
   file. No extra software or library needed.

2g. The birth certificate form now uses a 3-package price picker
   (same style as the passport forms), instead of one flat fee:
     Standard — 3 Months .............. GHS 170
     Express — 2–3 Weeks .............. GHS 500
     Premium — 2–3 Working Days ....... GHS 900

2h. The admin login page now has a show/hide (eye) toggle on
   every password field — login, and both new-password fields
   in "Change Password" — and a softly cross-fading background
   of office photos behind the login card, changing every few
   minutes. Purely decorative: if you haven't added the photos
   yet (see image/README.txt) it just shows the plain gradient
   background, nothing breaks. Adjust which photos are used or
   how often they change — search admin.html for "ROTATE_MS"
   and the four <div class="login-bg-slide" ...> lines just
   above the login card.

3. NEW: the admin dashboard can now be viewed from ANY device,
   not just the browser that received the form. This required
   adding a small serverless backend (the /api folder) backed
   by Vercel KV. See "CONNECT THE ADMIN BACKEND" below — it's
   the one new step you need to do after deploying.

   Until you connect it, the site works exactly as before
   (forms still submit, email still sends, and admin.html still
   shows anything submitted on that same browser/device via
   localStorage) — you just won't see submissions from other
   people's devices until KV is connected.

STEP 1 — CONFIGURE PAYSTACK
───────────────────────────────────────────────────────────
Open script.js and find:
  const PAYSTACK_PUBLIC_KEY = 'pk_test_your_paystack_public_key_here';
Replace it with your real key from dashboard.paystack.com
(use a pk_live_... key when you're ready to accept real payments).


STEP 2 — CONFIGURE EMAILJS
───────────────────────────────────────────────────────────
script.js already has EmailJS IDs filled in near the top:
  const EMAILJS_SERVICE_ID  = 'service_zce0q0u';
  const EMAILJS_TEMPLATE_ID = 'template_yvy3prj';
and further down for the service forms:
  const EMAILJS_SERVICE_ID_SVC  = 'service_zce0q0u';
  const EMAILJS_TEMPLATE_ID_SVC = 'template_yvy3prj';
Double check these match your EmailJS account, and that your
EmailJS public key is set wherever emailjs.init(...) is called
in script.js.


STEP 3 — DEPLOY TO VERCEL
───────────────────────────────────────────────────────────
1. Push this folder to a GitHub repo (or drag-and-drop deploy
   on vercel.com — both work, no build step is required).
2. On vercel.com, "Add New Project" → import the repo.
3. Framework preset: "Other". No build command needed.
4. Deploy.

Your site is now live, and the /api functions are automatically
deployed too (Vercel detects the /api folder on its own).


STEP 4 — CONNECT THE ADMIN BACKEND (Vercel KV)
───────────────────────────────────────────────────────────
This is the step that makes admin.html work from any device.
Takes about 2 minutes:

  1. Open your project on vercel.com
  2. Go to the "Storage" tab → "Create Database" → choose "KV"
  3. Name it anything (e.g. "exprove-data") → Create
  4. Click "Connect Project" and connect it to this project
  5. Redeploy the project (Vercel will prompt you, or just
     push any small change) so the new environment variables
     take effect

That's it — Vercel automatically injects the KV_REST_API_URL
and KV_REST_API_TOKEN environment variables that api/_kv.js
needs. No code changes required.

Once connected, admin.html will show a green "Cloud Synced"
badge at the top, and every new submission — from any visitor,
on any device — will appear when you log into admin.html from
anywhere.


STEP 5 — SET YOUR ADMIN PASSWORD
───────────────────────────────────────────────────────────
The default password is 'Exprove2026!' — change it before
going live, two ways:

  Option A — from inside the dashboard (recommended):
    Log in to admin.html, click "Change Password" in the
    header, and enter your current + new password. This
    requires Vercel KV to be connected (Step 4) — that's
    where the new password is stored (as a secure hash,
    never in plaintext).

  Option B — via environment variable (sets the STARTING
  password, before anyone has changed it from the dashboard):
    On Vercel — Project → Settings → Environment Variables →
    add ADMIN_PASSWORD with your chosen value, for all
    environments. Redeploy after adding it. Once someone
    changes the password from the dashboard (Option A), the
    dashboard-set password takes over and this variable is
    no longer used.

  The password is never stored in this codebase or visible in
  admin.html's page source — it's verified by the /api/login
  serverless function, not by JavaScript running in the browser.


STEP 6 — ACCESSING THE ADMIN PORTAL ONCE DEPLOYED
───────────────────────────────────────────────────────────
Once this site is deployed on Vercel, your admin dashboard is
just a normal page on your site — there's nothing separate to
install or connect to. From any device, any browser:

  1. Go to your site's URL with /admin.html on the end, e.g.
       https://your-project-name.vercel.app/admin.html
     (or https://yourdomain.com/admin.html if you've connected
     a custom domain in Vercel)

  2. Enter the admin password (Step 5 above — 'Exprove2026!'
     until you change it) and click Sign In.

  3. You'll land on the dashboard with every submission that's
     come in, as long as Vercel KV is connected (Step 4) — if
     it isn't yet, you'll only see submissions made on that
     same browser, and a "Local Only" badge will show at the
     top instead of "Cloud Synced".

Bookmark that /admin.html link, or add it to your phone's home
screen, for quick access. Nothing about the admin page shows up
in your site's normal navigation — it's only reachable by
typing/bookmarking that exact URL, which keeps it out of casual
visitors' way without needing a separate login system.


HOW SUBMISSIONS FLOW
───────────────────────────────────────────────────────────
  Client fills a form
        │
        ├─► Paystack payment popup (card / MoMo)
        │        │
        │        └─► on success:
        │              • saved to this browser's localStorage
        │              • emailed to you via EmailJS
        │              • sent to /api/submit → stored in Vercel KV
        │
  You open admin.html from any device
        │
        └─► fetches /api/submissions (password protected)
              + merges in anything still only in local storage
              → shows everything in one dashboard


PRICING NOTE
───────────────────────────────────────────────────────────
All three passport forms (New Application, Renewal, and
Missing Passport) share the same 5-package price picker.
The client picks a package and the amount charged updates
automatically:

    1. Regular    — 32-Page Booklet — 1 Month          — GHS 700
    2. Regular    — 48-Page Booklet — 1 Month          — GHS 1,050
    3. Expedited  — 32-Page Booklet — 15 Working Days  — GHS 1,100
    4. Regular    — 48-Page Booklet — 15 Working Days  — GHS 1,300
    5. Emergency Service — Within 48 Hours              — GHS 2,500

  To change a package's price, open passport-form.html and edit
  the data-price="..." attribute on the matching <input
  type="radio" name="service_tier" ...> tag, plus the displayed
  GHS amount just below it — then make the same edit in
  passport-renewal-form.html and passport-missing-form.html so
  all three stay in sync (they intentionally use identical
  pricing).

  Other services keep a single flat fee — edit the amount
  inside each form's handleServiceForm(...) call near the
  bottom of the file if these change:

    Birth Certificate Application ..... GHS 200
    Sole Proprietorship Registration .. GHS 800   (~3 weeks)
    Limited Company Registration ...... GHS 2,500


TESTING LOCALLY
───────────────────────────────────────────────────────────
You can preview the pages by opening index.html directly in a
browser, but the /api endpoints (and therefore the cloud sync in
admin.html) only work once deployed on Vercel — or locally via
the Vercel CLI:
    npm i -g vercel
    vercel dev
This spins up the /api functions locally too.
